Well-Architected review

Two passes against the six pillars of the AWS Well-Architected Framework. The first pass is on the first working deployment (8 Nov, before monitoring). The second is after the incident work (9 Nov).

What changed between the passes

  • Reliability, gap → adequate: after pass 1 we added the health check, the alarms and the tested restore. We also proved detection with a planned outage: alarm after 9 minutes.
  • Operational Excellence, adequate → good: incidents INC-01 to INC-05 were found and fixed. Each fix went into the scripts, so a rebuild cannot reintroduce it.

Which pillar we optimised for, and which we accepted as weaker

Optimised: Cost Optimization and Operational Excellence. This is a single-dealership demo on a student account, so the job was to run it cheaply and run it well.

Deliberately weaker: Reliability through redundancy. A second instance, a load balancer and a managed database would roughly triple the cost for a system with a handful of users. We chose fast detection plus a tested restore instead of high availability.

The one gap we would fix first

Security: console access. The account is operated through one federated full-access role, so there is no separate least-privilege identity per person and MFA cannot be shown per IAM user. We would fix this first because it is the control that protects everything else. The fix is IAM Identity Center with a permission set for operations, MFA enforced, and full admin only through a role switch. It costs nothing and takes under an hour.
