AutoHub Assistant: a used-car help desk, run properly on AWS

AutoHub Assistant answers customer questions for AutoHub Pre-Owned Motors, a made-up used-car dealership. Customers ask what cars are in stock, how trade-ins and financing work, and when they can test drive. The assistant answers only from the dealership's own information.

The presentation

Replace VIDEO_ID in site/pages/index.html with the YouTube ID of the recorded 5–8 minute presentation, then run python3 site/build.py.

What the system does

A customer opens https://dd56jth94yne6.cloudfront.net, signs in, and types a question such as “Which SUVs do you have under 1,000,000 pesos?”. AutoHub Assistant replies with the matching cars from the current stock list, with stock numbers and prices. It will not decide whether anyone gets a loan: it explains the steps and sends the customer to staff.

It is built on LibreChat, an open-source chat application, reskinned with a new name, logo, wording, dealership content and rules. The answers come from Google's Gemini model (free tier). Everything else runs in one AWS account in Sydney.

What was wrong with how it ran, and what we changed

Problem we foundWhat we changedProof
The app silently ignored its own settings (wrong name, wrong address, sign-ups off) because of a file-permission mistake. The settings file is now owned by the user the app runs as. The same fix stopped the search service from crash-looping. Incident INC-01
The assistant could not answer anything: first a bad API key, then Google retired the AI model we had chosen. The key is now tested with Google before it is saved. The model was switched to one confirmed to work. Incident INC-02
Our own 30-question test used up the AI model's free daily quota, so customers would have got errors. Switched to a model with its own quota within 2 minutes. Tests can now target a different model. Incident INC-05
Nobody would know if the site went down. A health check runs every 5 minutes through the public HTTPS address and feeds 7 alarms that email the operator. Real alert email
Chats would be lost if the server failed. The database is backed up to S3 every 6 hours and kept for 8 days. A restore was tested. Restore test
Secrets could have ended up in code. All 6 secrets live in AWS Parameter Store, encrypted. No key appears in the repository. Security table

What improved

Before these changes the assistant answered 0 of 30 test questions, because every request failed. After them it answers 29/30. Outages are now noticed within about 10 minutes instead of whenever a customer complains. The system can also be rebuilt from the repository with four scripts. Details and graphs are on the Results page.

Honest limitations

  • One server in one data centre: if it fails, the site is down until it is rebuilt (about 15 minutes). We chose this to keep costs low.
  • The assistant can still make mistakes, so customers must confirm prices and availability with staff. See the system card.
  • All data is invented. This is a teaching project, not a real dealership.
