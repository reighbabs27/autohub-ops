Baseline: the environment before our changes

The starting point is stock LibreChat as its own instructions deploy it: clone the repository, copy .env.example to .env, run docker compose up. This page lists what that gives you, so the improvements on the other pages have something to be measured against.

AreaStock LibreChat defaults (baseline)Why that is a problem for a dealership help desk
IdentityTitle “LibreChat”, LibreChat logo, model picker showing every provider, presets, agents, parametersCustomers see a generic AI tool and can switch models or prompts
ContentNone: the model answers from its general trainingIt would invent cars, prices and policies
Accesshttp://localhost:3080, no HTTPSPasswords and chats would travel unencrypted on a public server
Sign-upsALLOW_REGISTRATION=trueAnyone on the internet can create an account and spend the AI quota
Secrets.env.example ships fixed sample values for CREDS_KEY, CREDS_IV, JWT_SECRET, JWT_REFRESH_SECRET. The AI key is pasted into .env on diskAnyone who knows the public sample values can forge login tokens. The key sits in a plain file
Containersapi, MongoDB, Meilisearch, vector DB, RAG API, and in the latest version an admin panelNeeds about 4 GB of RAM. The admin panel crash-loops without its own secret
MonitoringNone: container logs only, no alarms, no metricsAn outage is noticed only when a customer complains
BackupsNone: MongoDB data lives in a local folderLosing the disk loses every user and conversation
AutomationNoneEvery check and backup depends on someone remembering
Audit / costNothing in placeNo record of who changed what, and no warning before a bill

We never ran the stock defaults on the public server. The deployment script replaced them from the first boot, so the security rows describe what the defaults would have exposed, checked against LibreChat's published .env.example. The quality baseline is a real measurement.
